# Research300 v3：审稿问题与验收标准

本文件把用户提供的 AAAI 2027 人工审稿意见转成可检查的证据要求。先完成 benchmark 的有效性、接入公平性与正式实验，再据结果收敛论文贡献。暂不扩充题目数量、工程范围或系统功能。

v2 投稿的 150 题、v3 的 300 题和 v3.2 的新输入/接入协议是不同评测版本。新版能力不能回填旧稿的实验，也不能追认旧 OpenClaw `paperEligible:false` 记录为正式证据。本次工作记录见审查目录。

## 一、哪些证据回答哪条意见

| 审稿问题 | 验收条件 | 当前边界 |
| --- | --- | --- |
| KL7C、Fnjw：Auto–Generic 同时改变多个因素 | 同一模型、题目、输入、工具能力、原生引擎和预算下做单因素移除；记录实际生效配置 | 已有消融开关不等于完成消融实验 |
| KL7C：语义裁判未经独立工程师校准 | 若保留旧语义成绩/“语义是主瓶颈”结论，需独立双人盲标、仲裁、混淆矩阵和不确定性；否则撤下该结论 | v3 的确定性物理评分不自动验证旧 GLM 裁判，也未覆盖旧交互集全部语义能力 |
| KL7C：OpenClaw 开发成绩进入正文 | 新协议下封存正式运行、原始失败/重试、源码/模型/预算/输入/采集器指纹；由资格检查决定能否进表 | 旧记录继续只作开发证据 |
| Fnjw：缺少领域外部 agent | 至少接入一个可复现的外部结构工程 agent；公开适配与能力范围；与通用运行时基线分开报告 | OpenClaw 使用同一领域工具包，不能独自回答领域 agent 对比问题 |

## 二、工程等价政策

目标是核对**同一个已指定物理问题**，不要求候选复刻原 JSON 编号；也不能因为一个控制响应接近就认定任意替代模型等价。

| 表示变化 | 规则与限制 |
| --- | --- |
| 节点、构件、材料截面或工况编号 | 通过几何、连接、所用属性、有效荷载和选择映射核对；报告仍需绑定正确物理对象/工况 |
| 同一直杆的串联细分 | 内部点必须共线、度为 2、无新增活动支承或质量；无间隙、重叠或新的物理连接；属性和荷载仍核对；释放/偏心等未支持情形不自动豁免 |
| 分布荷载拆分 | 位置、区间强度、合力和一阶矩共同一致；相同总合力不足以通过 |
| 2D/3D 表示 | 仅在封闭平面域、活动自由度和局部轴约定满足既有条件时等价，不把一般空间模型投影成平面模型 |
| 无活动物理意义的默认值 | 正负零、明确空集合、精确 SDK 默认值，以及所有相关自动控制关闭时的纯几何楼层表 |
| 截面审计标签 | 仅剥离已识别且结构正确的来源/证据/规则标签；刚度、面积、惯性矩、扭转常数等实际值仍检查。剥离标签不证明来源真实 |
| 节点质量 | 仅在明确未耦合静力分析中可不参与判定；动力质量及执行设置必须匹配 |
| 振型符号与归一化 | 使用质量加权 MAC，允许整体符号/尺度差异；不能免除质量、周期或模态设置检查 |
| 不同建模理想化 | 不属于已认证等价域。需在看新候选成绩之前确定可接受模型族、适用响应和审查流程；不能临时放宽以救分 |

对于结构不符合约定的已知审计标签，只有在诊断副本中移除这些标签后**全部其余检查通过**，才标 `needs_review`。如果还存在错误刚度、荷载、原生响应、报告或证据身份，保留 `candidate_failure`。诊断副本不能产生通过成绩，原始状态不修改。未知扩展字段继续参与严格比较。

## 三、数值判定与解释

响应值先统一到规定量纲。低中难度及动力请求的阈值来自每轮私有参考的 `requests[].tolerance`，不能用一个近似百分比替代全部题目的阈值。`audit_reviewer_evidence.py` 输出按分量、单位、绝对/相对容差统计的完整清单。

一般响应判定为 `|actual − reference| ≤ absolute + relative × |reference|`。零附近主要由绝对项约束，符号也属于判定对象。

| 检查项 | 当前阈值/规则 |
| --- | --- |
| L3/L4 位移包络、控制点原生值、带符号报告 | `absolute = 1e-8 m, relative = 1e-6` |
| L3/L4 构件端力/矩及单向接口力 | `absolute = 1e-6`（分别以 kN 或 kN·m 计），`relative = 1e-6` |
| 刚接接口位移 | `absolute = 1e-8 m, relative = 1e-6` |
| 材料体积目标 | `absolute = 1e-10 m³, relative = 1e-7` |
| 质量汇总 | `absolute = 1e-8 tonne, relative = 1e-6`；各节点质量另由物理比较器核对 |
| 请求的场景相对变化 | `absolute = 1e-7, relative = 1e-6` |
| 动力参数数值/数组元素 | `absolute = 1e-12, relative = 1e-10`；类别、监测对象等另作精确检查 |
| 峰值时刻 | `absolute = 1e-9 s, relative = 0` |
| 振型 | 与独立参考及实际原生振型的质量加权 `MAC ≥ 1 − 1e-6` |
| 物理模型 | 坐标阈值 `1e-8 m`；属性/荷载比较参数 `1e-6`，按比较器的分量、守恒和绝对下限规则执行；不能把它等同于上面的响应容差公式 |

连续误差报告应保留单位、实际值、参考值、绝对误差和相对于容差的误差，零参考值不报告无定义的相对百分比。物理问题不匹配或证据缺失的项应标为不可比较，不能填零或只在成功子集上报总体精度。该输出尚待接入全族正式结果，不能以本次回归通过率替代。

## 四、参考有效性与独立审查

保留三类不同证据：维护者从公开资料重建的输入审计；独立于生产后端的直接刚度/质量凝聚/Newmark 核验；实际指定引擎的封存执行结果。三者一致说明已执行的这些检查通过，不等于全库经过外部工程师审核。

独立审查采用两阶段：

1. 两名未参与题目或参考编写的结构工程师独立读取公开原件，按轮次重建几何、连接、支承、材料截面、荷载/质量及修订；记录来源位置、量纲、歧义和解释。此时不给参考、候选输出、候选身份或成绩。
2. 第一阶段结果封存后才展示参考与比较政策；记录一致项、有效替代表示、题目/参考错误及裁判误拒。分歧由第三名工程师仲裁，保留原始判断和修改记录。

已提供可复现的初始抽样方式：`family × level` 的 12 层，每层按公开固定种子的 SHA256 顺序取 5 题，共 60 题；选择不读取候选成绩。该批用于覆盖审核，不代表全库已经外部验证。发现系统性歧义或参考错误时，应扩展至对应模板/拓扑族，并建立新版本，不能覆盖旧题和成绩。分层等额抽样若汇总成全库估计，需要使用相应权重。

旧语义裁判的校准须单独抽样：覆盖成功/失败、各交互类型和分歧风险，不把裁判标签预先给工程师；报告裁判对仲裁标签的误接受/误拒、混淆矩阵及按 scenario 聚类的区间。新的输入盲审包不替代这项工作。

## 五、正式实验的最小设计

先固定同一输入协议、引擎/版本、工具与编程权限、调用/原生作业/时间预算、模型/视觉模型、温度及随机种子策略、重试规则、场景清单和源码指纹。相同工具数量不等于相同能力：能写 Python 或自编求解器的权限也必须匹配；内部原生调用计入预算。

- **基线**：通用 agent + 相同原生能力；OpenClaw + 相同领域工具包；至少一个有代码的领域 agent。各基线的完整覆盖成绩与共同支持子集成绩分别报告，不能只展示成功接入部分，也不让配置阻塞冒充模型失败。
- **组件归因**：Full、no-routing、no-knowledge、no-validation-gate、no-state-versioning、no-evidence-binding，先验证各开关实际生效、目标机制在任务中被触发。每个变体只改指定因素；不把 Auto–Generic 当单组件消融。若任务不触发某机制，应缩小结论而非强行解释零差异。
- **重复性**：正式配置每 scenario 做预先固定的 3 次尝试，INT 保持题内会话；同时报告单次通过、三次全过及不稳定比例。区间/配对比较以 scenario 为聚类单位，不能把相关轮次当独立样本。
- **分母与故障**：保留全部已签发轮次。`passed/candidate_failure/blocked_configuration/ungradable_evidence/needs_review` 分开列出。配置/采集未解决时不发布合格主成绩；基础设施恢复保存全部尝试并预先规定，模型失败不能重答取最好结果。
- **发表资格**：原生环境、真实采集器、评分规则和输入隔离均需独立验收；旧开发试验、synthetic 单元测试与离线正例重放均不能授予正式运行资格。

v3 的 test split 已用于全量开发验证与评分器修正，后续重跑应称冻结回归集实验。不能再次称作未见留出集泛化。若论文需要该主张，应另行保留按来源/拓扑族隔离、在调试结束后封存的外部测试集。

## 六、完成标准

本地评分器回归完成后，仍须补齐独立工程师审查、保留旧语义主张时的裁判校准、真实原生采集验收、同协议正式基线与匹配消融，以及连续误差/阶段交叉报告，才算回答了核心评测质疑。只增加题数、把已有统计重新包装或把 `paperEligible` 改为 true 都不满足这些条件。

bench 可以支持“在已覆盖线弹性问题和已检查字段上，交付与可追溯原生证据一致”的结论。它目前不支持“所有自由文本无幻觉”“完整规范设计可靠”或“人类审核更快”的结论；最后一项需要独立的人类审核实验。
