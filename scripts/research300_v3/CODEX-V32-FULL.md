# Codex v3.2 全量冻结回归

用户授权对当前所有题目做一次真实 Codex 尝试，并要求不 push。本轮范围为 `corpora/research300-v3-v1` 的全部 **300 题、560 轮**；不挑选上一轮成功答案，也不在作答过程中反馈评分。

本实验用于检查输入投递、真实原生执行、证据采集和确定性评估。它不是 StructureClaw 最新 `research_next` 整系统成绩，不授予论文正式比较资格，也不把已用于开发的 test split 重新称为独立留出集。

工具调用上限按 CLI 事件观测执行；发现超限即终止，第一个超限事件可能已开始。原生预算由控制端在执行前检查。两者的执行边界分别记录，不能把工具预算描述为原子执行前限制。

运行前复核了 Windows 上的 129 个冻结源文件，并分别真实调用 PKPM 和 YJK 做数值预检。预检使用单独的参考角色，不进入候选成绩。运行结束再次验证本地与远端源码。

## 证据与评估

`run_codex_full_v32.py` 在模型调用前封存源码、输入协议与预算。每次模型调用保留 dispatch、逐事件输出、stderr、原始交付和退出原因；控制端给每次原生请求分配独立身份，保留原始请求、软件输出、适配记录和回执。全部请求均进入本轮台账，包含失败、未被最终答案引用或在关闭边界被拒绝的请求。

`inspect_codex_full_case_v32.cjs` 只检查已经由控制端结束的案例。它核对实际投递字节、图片参数、隔离探针、线程连续性、原生输入与软件原始文件，以及结果封装是否改变原始值。该检查既不作答也不评分。

全量完成后，`grade_codex_full_v32.cjs` 要求控制目录之外的 SHA256 固定记录，并核对源码、题库和全部证据文件。分母固定为 300 题、560 轮；保留五类结果：`passed`、`candidate_failure`、`blocked_configuration`、`ungradable_evidence`、`needs_review`。中断或采集不全的轮次不能从分母删除。

`audit_codex_full_controls_v32.cjs` 在通过的原始答案副本上测试错误物理量、报告值、单位、身份、旧证据和篡改等情况；同时检查合法单位转换与实体顺序变化。它不修补失败答案作为正例，不写回原始状态，也不发起模型或原生调用。

`measure_codex_full_v32.cjs` 输出所要求标量、控制位置及接口量的连续误差；区分原生值对参考、报告对原生值。物理输入不符或证据不足的观察项明确标成不可比较，不能填零。该诊断不改变评分，也不等于对完整时程、任意自由文本或所有设计属性作了额外认证。

`summarize_codex_full_v32.py` 导出 300 题索引、560 轮状态、原始消息和答案。Excel 的答案按片段完整保留，重新打开导出文件后逐条重建字节并核对 SHA256。

`replay_codex_full_v32.py` 归档源码、公开工具、冻结题库和原始证据，在另一目录解压，以归档源码重新评分；要求完整诊断 JSON 逐字节一致。重放使用同一主机与 Node 环境，不调用模型或求解器。

## 本次运行中发现的环境故障

临时 SSH 认证代理在运行中退出，控制端记录到 `V3-INT-014` 和 `V3-INT-015` 共 4 次商业作业传输失败。其中一次远端作业实际结束，但结果未能在原轮次返回；事后收集的文件仅用于环境调查，不补填候选成功回执。代理路径恢复后，后续商业作业继续执行。

这暴露了一个归因缺口：CLI 正常结束并不保证原生环境可用。原始评分仍原样保留在 `diagnostic.json`；新增 `review_native_environment_v32.cjs` 对封存的控制端 SSH 故障回执及依赖该缺失状态的后续查询作单独复核，输出 `diagnostic-reviewed.json`。该**事后**规则不改变物理比较、答案或原生记录，不增加通过数，也不删除分母。候选自行声称“SSH 失败”不能触发该规则。若真实恢复后已经交付有效结果，仍按原始通过判定处理。

`finish_codex_full_review_v32.py` 自动生成该复核、连续误差、人工查阅导出和独立节点荷载见证，并在冷重放目录验证复核与连续误差文件逐字节一致。最终查阅优先使用 `review-adjudicated/catalogue.xlsx`，原始导出保留用于对照。

`run_codex_recovery_v32.py` 只允许选择有原始控制端传输失败回执的商业题，并等待原全量的所有商业工作流结束。补做时使用全新线程、原协议及原预算，结果单独封存，不替换全量原始成绩。其完整源码相对原驱动的改动与原环境故障回执一同保留。

未 push，也未发布结果。单次全量尝试和上述检查可以定位实际缺陷并建立可复查证据，不能证明评价器绝无缺陷。独立工程师审查、语义裁判校准、外部领域 agent 对比及匹配消融仍按 [REVIEWER-ACCEPTANCE.md](REVIEWER-ACCEPTANCE.md) 分别验收。
