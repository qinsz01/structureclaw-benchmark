# v3.3：静力工况结果按计算依赖复用

这是读取 2026-11-01 全量 Codex 交付后发现边界问题而建立的事后评分修订。v3.2 的源码、原始结果、题目、答案、原生回执及数值容差保持不变；新结果单列，不追认为预注册实验。

在 INT-016、019、020、023、027、029 的 t2 中，变更仅修改 Q。候选提交包含最新 Q 的完整模型并重新计算 SERVICE，同时复用旧 D 工况结果。v3.2 要求每个被引用作业的全部荷载工况都与当前模型一致，因旧 D 作业仍存有旧 Q 而拒绝。这把未参与 D 计算的荷载变化也当成 D 结果失效的原因。

v3.3 保留完整当前模型的证据要求，并允许有限的依赖复用：

1. 引用的受保护作业中，至少一个必须与完整当前物理模型匹配；不能仅用旧结果宣称已落实变更。
2. 对完整模型不一致的引用，只在 OpenSees 已完成的线弹性静力执行中考虑复用。自重自动生成、P-Delta、刚性楼板、刚域和施工阶段控制必须明确关闭；原生执行记录须证实线弹性、Linear 算法及 Static 分析成功。
3. 每份被引用作业至少须匹配一个被请求工况的实际有效物理问题。匹配继续检查几何、连接、支承、所用材料截面、活动控制和带符号有效荷载，不能只看某个响应值相近。
4. 每个请求仍读取原始作业的实际输出，检查对象、位置、方向、符号、单位及原容差；不从参考值生成候选数值，不修补候选模型。
5. 跨题/未来作业、未封存作业、查询轮偷偷执行、明确要求新执行却复用旧作业，继续由原规则拒绝。

已在合成边界测试中分别检查合法复用、活动荷载变化、刚度变化、缺少当前完整模型、报告符号错误、原生数值错误、缺少执行证明、显式新执行要求和查询轮执行约束。它们不是模型成绩或真实求解器执行。

`regrade_codex_full_v33.cjs` 对原 560 轮先重放 v3.2，核对其失败指标和原始作答哈希，再用 v3.3 重新评分；它不只修改六个状态标签。新增通过轮次还进行实际交付上的正反例检查。原环境故障归因和全部 560 轮分母保留。新源码、诊断及冷重放记录单独归档。

此边界修订不意味着任意缓存有效、不认证非线性/商业引擎跨版本复用，也不把未变化的一项响应当作整个工程交付正确。
