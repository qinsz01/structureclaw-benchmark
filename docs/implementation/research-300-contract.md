Authority: implement the approved 300-case benchmark plan; user prioritizes fast parallel execution and quality with unlimited token budget. Six named SSH author accounts are authorized. Only benchmark changes; legacy scenarios/fixtures and representative-18 are frozen. No production sclaw edits, no paid full agent trials. New data must not enter unrelated Windows development agents. The Windows solver host may receive numeric-only isolated native jobs, not prompts, attachments, answers or grading rules.

Keep supports, all exact numbers, topology, loads and requested outputs specified by each source row. Complete genuinely missing appendices with documented explicit values.

- Every `turns` entry: `id:"t1"`, `instruction` (correct locale), `state` (1-based model state or null while missing essential input), `expectation:"analyze"|"clarify"|"query"`, `attachments` (PUBLIC relative filenames visible newly in that turn), `unresolvedFields:[]`, `expectedQuestions:[]`, optional `changedFields`/`preservedFields` JSON pointers. Do not reference hidden models in instructions. INT must preserve original turn counts/edits/queries; first-turn clarify with missing data must not expose that data in attachments. A later clarify after earlier successful analysis is valid. Pure query can use prior state; actual edit needs current analysis. Missing physical inputs cannot use this exemption. Bind same-state turn outputs explicitly with `requiredOutputIds`, `requiredQuantityIds`, or output `turnIds`; later query targets must not leak into earlier turns.
- `requiredOutputs`: array of `{id,description,state,quantityIds,kind}` where `kind` is `numerical`, `derived`, `figure`, or `interaction`; each output phrase/position/case must be represented. Figure expectations are not fulfilled by numeric-only data. `requirementCoverage`: array `{sourceField,requirementIds,targets,notes}` covering ALL source requirement numbers (including execution/independent review policies honestly as pending policy requirements). Targets identify turns, public attachments, requested quantities, or explicit acceptance gates; never mark executable acceptance merely from text mapping.
- `reference-requests.json`: `{schemaVersion:1,states:[{state:1,model:"model-state-1.json",quantities:[...],derived:[]}]}`. Each quantity uses existing shape `{id,selection:{kind:"case"|"combination",id},location:{kind:"node",id}|{kind:"member",id,positionM,side:"left"|"right"},component,unit,tolerance:{absolute,relative}}` WITHOUT value. Node displacement components ux/uy/uz/rx/ry/rz, support components Fx/Fy/Fz/Mx/My/Mz, member N/V2/V3/T/M2/M3 and displacements as supported. IDs must be unique per state+selection; prefer IDs containing selection. Required midpoint displacement should be a real connected observation node or exact independently computed member station, never visual interpolation. Derived records `{id,operation:"difference"|"sum"|"max"|"min"|"max_abs",operands:[quantityId,...],unit,description}`; retain governing operand/selection and signed value for max_abs. Reference worker implements evaluation of these records.
- Default new-case tolerance is absolute 1e-8 + relative 1e-6 in declared units. Where the physical reference/engine requires another engineering tolerance, record justified frozen author decision before candidate runs; never tune against failures.
- Public input should include complete units, section/material properties and analysis settings. STD/INT may provide geometry tables as allowed by source. Architectural DXF and multi-view must honor source category. English tasks must have English prompts/attachment labels.

Never import SUT conversion/solver/postprocessing into oracle.
- Manifest built centrally from all case contracts, records source hashes, public/private files+hashes, counts and acceptance stages. No author writes global manifest/package.json/common schemas.
- New corpus provider APIs: `loadCorpus({corpus:'legacy-150'|'research-300',root?})`, `loadCase(corpus,id)`, `getPublicTurnInput(caseRecord,turnIndex)`. Keep explicit public input vs evaluator-only references and reject traversal/symlink escape or hidden-reference attachment paths. New CLI selection defaults legacy-150.

## Authored input binding
`sourceHash` is SHA256 of UTF-8 compact JSON `{"schemaVersion":1,"files":[{"path":"<case-relative POSIX>","sha256":"<raw-file SHA256>"},...]}`. Include `contract.json`, `prompt.txt`, every model state, `reference-requests.json`, and every public attachment, deduplicated and sorted by UTF-8 path bytes. Emit literal Unicode and keys in the displayed order. Exclude generated reference/native evidence to avoid circular hashes. Raw contract hashing alone is insufficient. Trusted reference evidence also binds state, expected physical model fingerprint and the independently checked reference artifact.

## Public response requirements
The provider publishes a versioned, per-turn `responseContract` containing the required report format, current output selectors and reporting units. It never publishes reference values, tolerances, hidden models, expected clarification wording, future targets, or private-only intermediate quantities. An evaluator cannot require secret quantity IDs or an undisclosed formatting rule. Derived results preserve signed values and governing selection/location; unrequested intermediate member values are calculation inputs, not mandatory report rows.

## Offline evidence evaluation
Only current assistant answers or a benchmark-observed current report emission satisfy report requirements. A query may reuse a matching previous solver run, but must answer the current request. Immutable run IDs bind exact raw solver context, engine/version, state, authored source, physical model, selected case/combination and artifact bytes. Cancelled, failed, preliminary or otherwise unsuccessful outputs do not become successful merely because they contain numerical arrays. Runtime/provider/evaluator versions are recorded separately from authored input hashes.

Semantic interaction review uses separately supplied benchmark-owned assessments bound to case, turn, output, source and current answer digest. Candidate-supplied assessment flags are not trusted. Missing review is pending configuration, never an invented pass. Native numerical agreement, input review and final acceptance remain separate stages.

## Extrema ties
For max/min/max_abs, determine the best score, then collect operands whose score differs by no more than the derived request's already frozen absolute-plus-relative tolerance. The canonical reference uses the first such operand and retains its signed value; `coGoverningOperands` records the complete ordered set. Optional request `tiePolicy` is `first` by default. With explicit `any`, a report may name any one co-governing physical location, but its sign and value must match that particular operand and its exact load selection. Numerical tolerances are unchanged. This prevents roundoff from flipping an equally large tension/compression pair into a false failure.
