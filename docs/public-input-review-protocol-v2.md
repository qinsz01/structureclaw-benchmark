# Public input reconstruction protocol v2

This protocol applies to the single current public input package. The implemented visual reconstruction grader supports MM cases; STD and INT input review remains a separate pending requirement. Historical review records do not certify changed inputs.


A reviewer receives one independently staged packet directory. Open only its `packet.json`, listed turn messages, public attachments, this protocol and `decoder.cjs`. Do not inspect repository source, authored SVG, hidden models, expected results, prior reviews or later-turn packets. For an initial turn, identify ambiguity from the delivered inputs yourself. The packet intentionally contains no ambiguity rubric or intended-skill inventory. A later-turn packet includes all earlier input history and the new correction.

Read the actual PNG drawings visually and DXF geometry where present. Recover node coordinates, member connectivity and direction, restraints, assignments, load positions/components, axis convention and section roll. Public JSON/text tables may be decoded automatically. The standalone decoder copies only explicitly tabulated properties, assignments and loads; it leaves drawing geometry/connectivity incomplete. Run `node decoder.cjs --reviewer YOUR_SESSION_ID > /outside-packet/submission.json`, then complete the readback. Do not copy a hidden model or mark your own result passed. Document uncertainty rather than guessing. Original node/member IDs must be retained; load-record IDs are arbitrary bookkeeping. Node/member order is otherwise immaterial, but each element's endpoint order defines its local axis and must match the visible arrow.

The submission is a JSON object with `schemaVersion:1`, `caseId`, `turnId`, `packetSha256` (SHA-256 of the exact packet.json bytes), `reviewer:{id,kind:"agent"|"human",independent:true}`, `method:"public-only-reconstruction"`, `model`, `unresolved:[]`, and `observations:[]`. Unknown model facts may be omitted or null. Units are m, kN, kN*m; E/G MPa, density kg/m3; section A m2 and Iy/Iz/J m4; roll degrees. No solver run or numerical response is required for this input review.

The exact machine-readable contract is `submission-schema.json`. Unsupported mechanisms, unit overrides and unknown fields cannot earn a pass. The coordinator seals original JSON before semantic validation, so nonconforming submissions remain inspectable.

`model` contains these public readbacks:

- `coordinate_system:{dimension:"2d"|"3d",plane:"xz"|null,semantics:"global-z-up",dof_order:["ux","uy","uz","rx","ry","rz"]}`.
- `nodes:[{id,x,y,z,restraints:[ux,uy,uz,rx,ry,rz]}]`, where each restraint is a Boolean (true means restrained). Account for public inactive-DOF and truss conventions. Null components can express unknown restraints.
- `elements:[{id,type,nodes:[startId,endId],material,section,rotation_angle}]`. Types include beam, column and truss. The actual public member type and assignment must be read; do not infer from this generic example.
- `materials:[{id,E,G,nu,rho}]` and `sections:[{id,properties:{A,Iy,Iz,J}}]`. Extra descriptive labels are ignored; all listed numeric stiffness properties are checked. Section shape dimensions are descriptive and are not independently certified. Optional `shape_units:"m"|"mm"` applies only to `shape`; it never converts A/I/J. Units on physical properties remain fixed. The verdict specifically covers physical stiffness and assignment.
- `load_cases:[{id,loads:[{id,type,reference_frame,node|element,fx,fy,fz,mx,my,mz,wx,wy,wz,start,end,extent}]}]`. Include only applicable target/component/extent fields. `start` and `end` are distances in metres from the listed first endpoint, NEVER fractions of member length. For a full-member distributed load, omit both or write `extent:"full-member"` without start/end. Explicit numeric intervals are compared in metres. Null means unknown and does not trigger defaults. Types and extents follow the public load records; global and element-local directions must be explicit. For a load unknown in this turn, preserve its known target/type and omit only the unknown component. `load_combinations` holds the exact public combinations or `[]` when none apply.
- `analysis_control:{self_weight,rigid_floor,p_delta,rigid_offsets,construction_stage}` with observed Boolean settings. Optional `first_order`, `linear_elastic`, `stiffness_reductions`, `automatic_combinations`, and `full_explicit_stiffness` are accepted only where the released public convention establishes their values; wrong values fail and unsupported settings are reported. Do not guess missing conventions. A structured `analysis:{type:"first-order linear elastic static",full_explicit_stiffness,automatic_reduction}` can express the same publicly established settings; contradictory aliases fail.
- `axes:{mode:"xz"|"reference-vectors",elementDirection:"listed-node-order",rotationDefaultDegrees:0}` only when a zero default roll is actually supported. Explicit element rotation overrides that default. In 3D also provide `metadata:{elementReferenceVectors:{memberId:[x,y,z]}}` from public assignments. XZ means local y before roll is global +Y; reference-vectors means local y = reference cross local x, then local z = local x cross local y. If the public appendix states a common reference-vector rule, an alternative is `axes.referenceVectorRule:{vertical:[1,0,0],other:[0,0,1],verticalThreshold:0.9}`; use it only when those directions apply to the observed members. The rule selects vertical when absolute unit local-x Z exceeds the given threshold. Explicit vectors take precedence. Comparison checks the vectors and signed member direction; arbitrary roll defaults must not be guessed.

For every category `geometry`, `topology`, `restraints`, `materials`, `sections`, `loads`, `axes`, `settings`, include an observation `{category,files:["t1/input.png"],observation:"What I actually read, and any derivation used"}`. Use exact packet paths. Geometry/topology/restraints need PNG or DXF evidence. Other categories may cite public table files. This evidence is part of the sealed reconstruction, not a promise to inspect later. A category missing source observations receives partial status even when its submitted values happen to match.

For unclear facts use `unresolved:[{kind,ids,component,reason,question}]`. Kinds are `load-component`, `node-coordinate`, `element-section`, `node-restraints`; `ids` are affected public node/member IDs, and `component` is the affected coordinate or force component where applicable. For `element-section`, omit component or use `"section"`; these are equivalent. For node-coordinate/load-component, specify the exact coordinate/force component. For node-restraints, omit component to ask about all active DOFs or list exactly the affected DOFs. Supply a targeted question and explain the visual/textual problem. Do not fill unknown values from drawing scale if the source is schematic. State derived unknown coordinates too. A new ambiguity on an otherwise complete turn is an unresolved observation, not a pass.

Large regular structures may use explicit observed expansion rules in `model`. A grid is `{stations:{x:[...],y:[...],z:[...]},idTemplate:"n{i}-{j}-{k}",restraints:[...],omit:[[i,j,k]],members:[{axis:"x",starts:[[i,j,k]],idTemplate:"e{i}-{j}-{k}",type,material,section,rotation_angle}]}`. The station arrays are actual observed coordinates. Every index is zero-based. A member starts at the listed grid index and ends at the next station on its declared axis. `omit` removes genuinely absent grid nodes; list each observed member start explicitly so openings and missing bays are not filled by assumption. `nodeOverrides:[{id,restraints,...}]` applies observed exceptions. `memberChains:[{nodes:["a","b","c"],ids:["ab","bc"],type,material,section,rotation_angle}]` expands a sequence of explicitly observed segments. Explicit nodes/elements can supplement these rules; duplicate IDs are rejected. No rule reads a gold model.

The coordinator records actual reviewer/session identity and dispatch provenance, then seals exact submission, provenance and packet bytes before any hidden comparison. Provenance contains `schemaVersion:1`, the same `reviewer`, `method`, `packetSha256`, `inputScope:"packet-only"`, `authoringParticipation:false`, `hiddenAccess:false`, `freshContext:true`, and a nonempty `dispatchEvidence` describing the real isolated dispatch/session. This is an auditable coordinator attestation, not cryptographic proof of a person's independence. Never fabricate it or use an authoring/audit agent as the independent reviewer.

The grader reports separate physical, protocol, clarification and source-observation dimensions. Overall pass requires all mandatory dimensions to pass. A protocol failure does not by itself establish a physical reading error; an uninterpretable physical model is explicitly ungradable. Physical load records are compared as a multiset: record IDs and ordering are bookkeeping, while multiplicity, targets, frames, signs and numeric intervals remain mandatory.

Only source-path/hash-bound public relative geometry may be used to derive lengths when absolute coordinates are unknown. No hidden expected coordinate may fill a submitted coordinate or an unknown load span. If a full span cannot be numerically determined from disclosed facts, retain the symbolic full-member extent rather than guessing a number.

After sealing, a separate grader compares disclosed physical facts to the frozen model. Numeric tolerance is max(1e-10 absolute, 1e-7 relative), accommodating printed appendix precision. Missing facts yield partial status; wrong facts yield failed status. The five staged ambiguity cases exclude only their genuinely undisclosed values and derived unknowns while checking that the reviewer independently asks the necessary clarification. A case passes only when every turn has complete, correctly bound evidence. Frozen acceptance/inputBlindReview is never updated. Grader version is physical-readback-v2; the legacy v1 grader and protocol remain available for historical replay. Old packets may be diagnosed separately but cannot be silently certified as fresh v2 reviews. Every replay verifies current inputBinding, packet files, submission bytes, provenance, receipt, grader source hash and recomputed coverage/verdict. A code/input change requires regrading; changed input requires a new public-only review.

Coordinator CLI (run from the repository; reviewers do not run these commands):

```sh
node scripts/research300/blind_input_review_v2.cjs export --ids MM-001,MM-007 --turn t1 --out /staging/initial
node scripts/research300/blind_input_review_v2.cjs seal --packet /staging/initial/MM-001/t1 --submission /reviewer/submission.json --provenance /coordinator/provenance.json --out corpora/research-300/input-reviews/MM-001/t1
node scripts/research300/blind_input_review_v2.cjs grade --ids MM-001 --evidence corpora/research-300/input-reviews/MM-001/t1
node scripts/research300/blind_input_review_v2.cjs verify --ids MM-001
```

Use `--turn t2` in a separate staging root when releasing corrections. `--turn all` exports all stages and is for coordinator storage only; never expose that parent directory to initial-turn reviewers. For multi-turn grading pass comma-separated evidence directories in turn order. Export does not authorize any external model or network call.
